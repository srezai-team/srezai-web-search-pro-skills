# Ошибки и восстановление

## Коды

| Код | Что значит | Что делать |
|---|---|---|
| `401 unauthorized` | ключа нет, он отозван или неверен | проверить `srezai whoami`; получить ключ: `srezai register --email …` (новый email) или кабинет |
| `402 insufficient_funds` | не хватает кредитов | сказать человеку баланс и ссылку на пополнение; не повторять вызов |
| `403 forbidden` | лимит тарифа или закрытый инструмент | не обходить; предложить другой инструмент/тариф |
| `429 rate_limited` / `trial_limit_reached` | лимит по ключу или дневной триал (25/сутки на IP) | CLI сам делает до 3 попыток с `Retry-After`; вручную не зацикливать; подождать или взять ключ |
| `503 service_unavailable` | сервис временно недоступен | 3 попытки, затем сказать человеку и остановиться |
| `ssrf_blocked`, `host_unresolved` | адрес запрещён серверной защитой | не искать обход, взять другой источник |
| `schema_invalid` | схема извлечения не по формату | сокращённая схема: `{"title":"string","price":"number?"}`, `?` — необязательное, `[]` — массив |
| `bad_request` | параметры не те или не JSON | свериться со справкой команды `srezai <cmd> --help` |

## Принципы

- Не ретраить 401/402/403/400 — повтор не поможет.
- Не подменять инструмент молча: если srezai недоступен, сообщить человеку код и
  цифры (лимит, баланс), а не искать обходной путь.
- `verify_claim`: вердикты `unverified` и `mixed` — честный результат, а не сбой.
  Не переформулировать утверждение, пока не сказал об этом человеку.
- `deep_research`: синхронный вызов обрывается около 150-й секунды. Долгие темы —
  только `--async` и опрос по талону.

## Деградация посреди пайплайна

Ошибка посреди задачи — не повод начинать заново и не повод падать. Спускайся
на дешёвую ступень и сохраняй уже собранное.

| Что пришло | Куда деградировать | Чего нельзя |
|---|---|---|
| `401` | ключа нет вовсе: без него работают `search`, `read`, `transcript` (25 запросов в сутки на IP) — пройти задачу дешёвой ступенью | вставлять ключ в чат/файлы, искать «обход» авторизации |
| `402` | кредитов нет: назвать баланс, остановить платные вызовы, отдать собранное. Пробный режим — только когда ключа нет, заменой баланса он не служит | повторять платный вызов «на удачу», дробить его на много мелких |
| `429` / `trial_limit_reached` | ждать `Retry-After` (CLI сам делает до 3 попыток); дневной лимит — остановиться до сброса окна | зацикливать вызов, менять ключ ради обхода лимита |
| `read_failed`, `upstream_timeout` | 1–2 повтора того же вызова, затем `read` другой страницы или `search` по теме | повторять `read` того же адреса больше двух раз |
| `search_unavailable` | 1–2 повтора, затем сказать «поиск недоступен»; опираться на уже найденное | выдавать старую выдачу за свежую |
| `503` | 3 попытки, затем зафиксировать и остановиться: сервис лежит, `search` тоже не ответит | изображать, что данные получены |
| `blocked` / `thin` (сайт закрыт) | другой источник по той же теме | повторять тот же адрес; выдавать меню/заглушку за данные |
| `schema_invalid` | исправить схему, 1 повтор | перебирать варианты схемы десятками |

Правила этой таблицы:

1. **Не перезапускай весь пайплайн**: сохрани то, что уже прочитано/проверено,
   и продолжай с места сбоя.
2. **Не выдавай частичный результат за полный**: назови, что именно не удалось,
   и какая ступень не доработала.
3. **Не меняй канал молча** (CLI → MCP → REST): те же кредиты, другой контекст;
   если менял — скажи.
4. **Не выдумывай данные вместо упавшего вызова**: пусть лучше в отчёте будет
   «не прочитано», чем подставленная цифра.
5. **Бюджет важнее энтузиазма**: если деградация уже съела потолок задачи,
   остановись и отчитайся (см. [economy.md](economy.md)).

- Что уже собрано и на что можно опираться.
- Что не проверено.
- Что нужно от человека: пополнить, подождать, дать ключ, сменить источник.

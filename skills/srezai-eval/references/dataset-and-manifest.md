# srezai-eval — датасет, манифест, судья

Три вещи, без которых прогон нельзя повторить: зафиксированный датасет,
неизменяемый манифест и судья с записанным промптом. Всё остальное — производные.

## Датасет

### Откуда брать вопросы

1. Реальные вопросы из тикетов, чатов поддержки, логов агента — с разрешения
   владельца данных.
2. Задачи, на которых сервис реально зарабатывает: поиск факта, чтение
   документа, сравнение, проверка утверждения.
3. Добавь сложные случаи, которые обычно ломаются: свежие данные, русские
   сайты, PDF, страница без даты, противоречивые источники, вопрос без ответа.

Не составляй датасет из примеров, которые уже видел в промпте/доке, — это
утечка и завышенное качество.

### Размер и состав

- 30–100 вопросов: меньше — шум, больше — дорого и долго.
- Стратификация: категория (факт / сравнение / процедура / проверка / свежесть),
  язык (ru / en), сложность (1–2 шага / 3+), тип источника (сайт, PDF, видео).
- 50–70 % — dev: на нём можно смотреть ошибки и править конфигурации.
  30–50 % — holdout: трогаешь только в финальном прогоне.
- Каждый вопрос — одна строка JSONL:

```json
{"id":"q007","question":"Ставка НДС для IT-услуг в России в 2026?","language":"ru",
 "category":"fact","difficulty":1,"expected":{"facts":["20%"],"sources":["nalog.gov.ru"]},
 "notes":"принимается ссылка на НК РФ или официальное разъяснение"}
```

- `expected` — минимальное доказательство, а не эталонный текст. «Факт + какой
  источник его закрывает» проверяемо; «ответ слово в слово» — нет.
- Вопрос без ответа (`unanswerable`) — обязательный класс: проверяет, умеет ли
  система сказать «не подтверждено», а не выдумать.
- Персональные данные, внутренние адреса и ключи в датасет не попадают.

### Версионирование

- Файл `dataset/<name>.jsonl`, рядом `dataset/<name>.sha256` и короткий README:
  откуда вопросы, когда собраны, что считается правильным.
- Изменил датасет — новый хэш и новый манифест. Сравнивать прогоны на разных
  версиях датасета нельзя, даже если «вопросы почти те же».

## Манифест

Один JSON на прогон, неизменяемый после старта. Повторный запуск — новый файл с
тем же `dataset.sha256` и `configs[].id`.

```json
{
  "run_id": "2026-11-20T18-40_srezai-v0.6.0",
  "created_at": "2026-11-20T18:40:12+03:00",
  "skills_version": "0.6.0",
  "api": {"channel": "cli", "endpoint": "https://srezai.ru/api/mcp", "mode": "paid"},
  "dataset": {"name": "support-facts", "sha256": "…", "n": 60, "split": "holdout"},
  "configs": [
    {"id": "search-5", "tool": "web_search",
     "params": {"num": 5, "depth": "auto", "language": "ru"}},
    {"id": "answer-balanced", "tool": "answer_search",
     "params": {"depth": "balanced", "language": "ru"}},
    {"id": "deep", "tool": "deep_research", "params": {"async": true}}
  ],
  "runs_per_config": 3,
  "judge": {"model": "…", "prompt_sha256": "…", "temperature": 0, "scale": "0-3",
            "blind_to_config": true},
  "budget_credits": 400,
  "balance_before": 1234,
  "artifacts": {"items": "runs/<run_id>/items.jsonl", "raw": "runs/<run_id>/raw/",
                "report": "runs/<run_id>/report.md"},
  "notes": "сравниваем глубины answer; судья не видит провайдера"
}
```

Обязательные свойства: дата, версия скиллов/API, канал, полные параметры
каждого инструмента, хэш датасета, судья с промптом и температурой, число
прогонов, бюджет и баланс до/после. Если чего-то нет — прогон не воспроизводим.

Заморозка: после первого вызова манифест не правится. Нашёл ошибку — новый
`run_id`.

## Судья

### Рубрика

Оценивай по пунктам, а не «нравится/не нравится». Минимальный набор критериев:

| Критерий | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| Факты | ключевые факты неверны | половина неверна | верно, есть неточности | все ключевые факты верны |
| Подтверждение | цитат нет/не по теме | ссылка есть, цитата не подтверждает | подтверждает частично | каждая цитата подтверждает тезис дословно |
| Полнота | не отвечает на вопрос | отвечает на часть | отвечает, но упускает существенное | отвечает полностью |

Если вопрос `unanswerable`, «3» — честное «не подтверждено» с объяснением, а
«0» — выдуманный ответ. Это записывается в рубрику заранее.

### Обязательные требования

- Судья **не видит**, какая конфигурация/провайдер дал ответ: убери имена,
  заголовки, служебные метки. Порядок ответов перемешан.
- Один и тот же промпт, модель и версия — для всех конфигураций; фиксируются в
  манифесте (`prompt_sha256`, `temperature: 0`).
- Судья обязан вернуть **обоснование** и цитируемый фрагмент. Оценка без
  обоснования не считается.
- Если нужен pairwise («A или B»), сравнивай только ответы **одного класса
  задачи** и меняй A/B местами; позиция влияет на выбор.
- Проверь судью: 10–15 % ответов разметь человек, посчитай совпадение. Низкое
  совпадение — сначала чинить рубрику, а не доверять цифре.

### Чего судья не должен делать

- Получать эталон и подсказку «правильный ответ — …», если это раскрывает
  конфигурацию.
- Оценивать объём («длиннее — лучше») или стиль вместо фактов.
- Быть той же моделью, что синтезировала ответ, без перекрёстной проверки
  человеком: самопредпочтение искажает результат.

## Протокол прогона

1. Dry-run на 3 вопросах: проверить ключ, лимиты, манифест, парсер ответов.
   Стоимость — единицы кредитов, ошибки дешевле поймать здесь.
2. Полный прогон: порядок `config × item × run` перемешан; параллелизм не выше
   burst-лимита, иначе 429 начнёт искажать латентность.
3. После каждого вызова сразу пиши строку: `run_id`, `config_id`, `item_id`,
   `run`, `status`, `code`, `latency_ms`, `credits`, `answer_sha256`,
   `answer_path`, `judge_score`, `judge_reason`. Сырой ответ — в файл, не только
   в контекст.
4. Стоп-правила: при `402` — остановиться и зафиксировать, сколько выполнено;
   при серии `429` — снизить параллелизм, а не выкидывать попытки.
5. Итог: `items.jsonl` + `raw/` + `report.md` — всё лежит рядом и переживает
   сессию.

## Что считается ошибкой эксперимента

- Датасет собран после того, как посмотрел ответы.
- Конфигурация менялась посреди прогона.
- Неудачные попытки удалены из выгрузки.
- Судья видит название провайдера.
- Сравниваются прогоны с разными датасетами/судьями/каналами.
- Победитель выбран по лучшему из трёх прогонов.

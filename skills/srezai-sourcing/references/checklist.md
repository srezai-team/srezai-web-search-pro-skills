# Чек-лист прохода и формат отчёта

## До поиска

- [ ] Товар назван конкретно (тип, материал, применение), а не «товар из Китая».
- [ ] Понятны ограничения: регион/кластер, объём, MOQ, бюджет, срок.
- [ ] Решено, что считаем результатом: 5–10 кандидатов или обзор кластеров.

## Поиск

- [ ] EN-проход: обзор, кластер, 2–3 экспортёра.
- [ ] `site:`-фильтры опробованы; пустой результат — снять фильтр, не расширять вслепую.
- [ ] ZH-проход: 1688, zhihu, сайты рынков/`gov.cn`.
- [ ] Для каталогов и рынков сделан `map`, читались только выбранные страницы.
- [ ] Всего потрачено не больше 15–25 вызовов: `search` → `map` → `read`/`extract`.

## Карточки

- [ ] На каждого кандидата — карточка по схеме (`supplier-card.md`).
- [ ] У цены есть валюта, единица и дата.
- [ ] У адреса и юрлица — источник; иначе поле пустое.
- [ ] Тип помечен: фабрика / трейдер? / неясно.
- [ ] Ни одно поле не перенесено с другого кандидата.

## Проверка

- [ ] Спорные утверждения прогнаны через `verify`.
- [ ] В таблице есть колонка «Подтверждено» и в ней — не «✓» без ссылки.
- [ ] Противоречия названы, а не сглажены.

## Стоп-правила

- **Стоп, когда** набрано достаточно кандидатов и по каждому ясно, что
  подтверждено, а что нет. Добавлять 20-го кандидата, когда у 5 нет адреса, —
  трата кредитов.
- **Стоп, если** три запроса подряд пустые: проблема в формулировке или
  канале, а не в отсутствии фабрик.
- **Стоп, если** источник противоречит сам себе — писать человеку, не «догадываться».
- **Не начинать** `crawl` по маркетплейсу: сотни страниц без отбора — переплата.

## Формат отчёта

```markdown
# Поставщики: <товар> · <дата>

## Что искали
Кластер/регион, MOQ, бюджет; какие каналы использованы.

## Кандидаты
| # | Кандидат (EN / ZH) | Город | Тип | MOQ | Цена | Подтверждено |
|---|---|---|---|---|---|---|

## Подтверждения и пробелы
- адрес: подтверждён / одна ссылка / нет;
- юрлицо: …
- сертификаты: …

## Что делать дальше
Писать каким кандидатам, какие вопросы задать (MOQ, образцы, сроки),
какие поля доуточнить.

## Источники
Ссылки на страницы, откуда взято каждое ключевое поле.
```

## Чего не делать в отчёте

- Не писать «поставщик проверен» — мы проверяем поля, а не людей.
- Не выдавать список ссылок за подборку поставщиков.
- Не скрывать, что часть данных не подтверждена: это и есть ценность отчёта.

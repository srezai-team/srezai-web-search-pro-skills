# srezai-migrate — пошаговый чек-лист переезда

Порядок важен: сначала инвентаризация и честная классификация, потом код.
Пропущенный шаг «чего у нас нет» всплывает в проде как сломанная функция.

## 0. Зафиксируй исходное состояние

- [ ] Список вызовов старого провайдера с частотой и стоимостью за месяц.
- [ ] Список функций, которые этими вызовами закрываются (а не список эндпоинтов).
- [ ] Метрики «до»: доля пустых ответов, p50/p95, стоимость на задачу. Без них
      «стало лучше» не проверить.
- [ ] Кто ещё использует ключ/аккаунт старого провайдера — чтобы не отключить
      чужое.

## 1. Инвентаризация: где живёт провайдер

```bash
# имена провайдеров и их SDK/эндпоинты
grep -rniE 'tavily|firecrawl|exa[-_.]|serper|serply|searchapi|serpapi' \
  --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=vendor .

# ключи и env
grep -rnE 'TAVILY_API_KEY|FIRECRAWL_API_KEY|EXA_API_KEY|SERPER_API_KEY|SERPLY_API_KEY|SEARCHAPI_API_KEY|SERPAPI_API_KEY' .

# адреса API
grep -rnE 'api\.tavily\.com|api\.firecrawl\.dev|api\.exa\.ai|google\.serper\.dev|serply\.io|searchapi\.io|serpapi\.com' .

# зависимости
grep -rnE '"(tavily|firecrawl|exa|serper)[a-z0-9@/_-]*"' package.json 2>/dev/null
grep -rnE '^(tavily|firecrawl|exa|serper)[a-z_-]*' requirements*.txt pyproject.toml 2>/dev/null
```

Дополнительно проверь руками: `.env*`, CI-конфиги, docker-compose, k8s-секреты,
промпты и доки, клиентские бандлы (там ключа быть не должно), скрипты разовых
задач, n8n/airflow-воркфлоу, тексты ошибок пользователю.

## 2. Классификация

Для каждого найденного вызова ответь письменно:

| Вопрос | Если «нет» |
|---|---|
| Есть ли строка в `mapping.md`? | функция уходит в «нет аналога» |
| Совпадает ли семантика (не только имя)? | переписать логику, а не только URL |
| Укладывается ли в лимиты (≤10 ссылок, ≤20 страниц, ≤30 результатов)? | разбить на батчи или сменить подход |
| Нужны ли поля, которых у нас нет? | оставить старого провайдера на этом участке |

Результат — таблица «вызов → наш инструмент / гибрид / удалить». Согласуй её с
человеком до кода: это дешевле, чем переделывать после.

## 3. Адаптер, а не замена строк

- [ ] Один внутренний интерфейс (например, `search(query, opts)`, `fetchPage(url)`).
- [ ] Реализация srezai внутри; старую можно оставить второй реализацией.
- [ ] Поля ответа приводятся к внутренней модели; наружу не течёт `results[].score`
      вместо `relevance` и наоборот.
- [ ] Ошибки старого провайдера больше не ловятся по тексту — только по `code`.
- [ ] Никаких `catch (e) { return [] }`: пустой ответ и сбой различаются.

## 4. Ошибки и деньги

| Старый код/случай | Новый | Действие |
|---|---|---|
| 401/403 ключ | `401` (`missing_key`, `invalid_key`, `revoked_key`) | падать, ключ проверить |
| 402/депозит | `402 insufficient_funds` | стоп, сообщить человеку |
| 429 лимит | `429` (`rate_limited`, `key_limit_reached`) | `Retry-After`, backoff ≤3 |
| 5xx/таймаут | `502/503/504` | 3 попытки, затем деградация |
| пустой результат | `200` + пустые данные | не ретраить, менять запрос |

- [ ] `get_usage` до и после батча; сверить кредиты с логом.
- [ ] Бюджет на задачу; алерт на 402 и на суточный перерасход.
- [ ] Лимиты burst/квоты читаются из `X-RateLimit-*`, не захардкожены.
- [ ] Батчи: `read_urls`/`extract` ≤10 ссылок, `crawl` ≤20 страниц, `map` ≤200.

## 5. Тесты

- [ ] Фикстуры старого ответа → новый адаптер: поля не пустые, форма совпадает.
- [ ] Тест на 401/402/429/503/таймаут через подменённый транспорт.
- [ ] Тест «пустой результат ≠ ошибка».
- [ ] Один end-to-end сценарий из реальной задачи, а не только unit.
- [ ] Сравнение качества на реальных вопросах по методике
      [../../srezai-eval/SKILL.md](../../srezai-eval/SKILL.md): одинаковый
      датасет, судья, ≥3 прогона.

## 6. Чистка

- [ ] Удалены SDK/зависимости старого провайдера (или оставлены осознанно для
      гибрида и помечены).
- [ ] Удалены ключи из env/секретов/CI, `.env.example` обновлён.
- [ ] Удалены мёртвые URL, константы, ветки, комментарии «пока оставим».
- [ ] Обновлены доки, runbook, инструкция для поддержки.
- [ ] Финальный grep (шаг 1) пуст — либо каждое совпадение объяснено.

## 7. Проверка после переезда

- [ ] Smoke: `whoami` → `search` (1–3 результата) → `read` короткой страницы →
      `get_usage`. Стоимость — единицы кредитов.
- [ ] Ошибки: ключ без прав, пустой баланс, исчерпанная квота — сообщения
      понятные, без ключа в тексте.
- [ ] Латентность: p50/p95 не хуже «до» или отклонение объяснено.
- [ ] Деньги: кредиты на задачу в пределах сметы; нет двойных вызовов.
- [ ] Качество: доля пустых/нерелевантных ответов не выросла; честно названы
      потерянные функции.
- [ ] Наблюдение на неделю: 401/402/429, расход, p95, алерты.

## 8. Откат

- [ ] Старый ключ не отозван до подтверждения недельного наблюдения.
- [ ] Адаптер позволяет вернуть прежнюю реализацию флагом (или git revert без
      конфликтов).
- [ ] Известно, какие данные придётся перечитать: кэш нового провайдера не
      совместим со старым.
- [ ] Если гибрид — описано, какой участок на каком провайдере и почему.

## Красные флаги

- «Заменим URL и заработает» — почти всегда ломается семантика лимитов и полей.
- «Мониторинг сделаем сами на cron» без истории и дедупликации — получится
  уведомление о каждом изменении, а не монитор.
- «Сравним цены за вызов» — у нас плата за страницу/ссылку и кредиты; считать
  надо на своей нагрузке.
- «Потерянные функции не важны» без списка — через месяц выяснится обратное.

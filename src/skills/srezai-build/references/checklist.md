# srezai-build — чек-лист перед релизом

Проходить целиком до выката интеграции. Пункты — проверить руками или тестом,
не «на глаз». Цифры цен и лимитов инструментов — в `src/tools.json`; коды ошибок
и правила деградации — в [../../srezai-web/references/errors.md](../../srezai-web/references/errors.md),
контракт каналов — в [integration.md](integration.md).

## 1. Конфигурация и ключ

- [ ] `SREZAI_API_KEY` приходит из окружения/секрет-хранилища; в коде, `.env.example`,
      тестах и фикстурах — только заглушка `srz_live_…`.
- [ ] Ключ не попадает в клиентский бандл (browser/mobile): все вызовы через бэкенд.
- [ ] Отдельный ключ на окружение/сервис; известен порядок отзыва и замены.
- [ ] В логах, трейсах, метриках нет `Authorization` и полного ключа; ошибки не
      печатают тело запроса с пользовательскими данными.
- [ ] `git grep -nE 'srz_live_[A-Za-z0-9_-]{6,}'` — пусто; то же в CI (секрет-скан).

## 2. Один вызов на единицу работы

- [ ] Нет двойного вызова из-за ретраев, повторного рендера, хуков и watchdog.
- [ ] Кэш и single-flight: одинаковые запросы не уходят дважды.
- [ ] Таймаут и отмена на каждый вызов; отменённый запрос не порождает второй.
- [ ] Для `deep_research` — только async-талон и опрос; нет запроса, живущего
      минуты в HTTP-обработчике.

## 3. Ошибки — по коду

- [ ] `401` — падение с понятным сообщением; не ретраится.
- [ ] `402` — остановка и сообщение человеку; нет цикла «добьём мелкими вызовами».
- [ ] `429` — `Retry-After` соблюдается, backoff с jitter, попыток ≤3.
- [ ] `502/503/504` — 3 попытки, затем деградация или явная ошибка.
- [ ] `400`/`ssrf_blocked`/`schema_invalid` — не ретраятся, вход исправляется.
- [ ] Смысловые «пустые» ответы (`empty_result`, `null` в `extract`,
      `mixed`/`unverified`) обрабатываются как результат, а не как сбой.
- [ ] Тесты на подменённом транспорте покрывают 401/402/429/503/504/таймаут.

## 4. Деньги

- [ ] `get_usage` вызывается до батча и после — расход сходится с логом.
- [ ] Есть потолок кредитов на задачу/арендатора; при исчерпании — стоп.
- [ ] На `402` есть алерт; на аномальный суточный расход — тоже.
- [ ] Дешёвая ступень не заменена дорогой: `search` до `deep`, `extract` только
      когда поля известны заранее, `crawl` после `map`.
- [ ] Батчи не превышают лимиты инструментов, а не «сколько влезло».

## 5. Лимиты и параллелизм

- [ ] Семафор ограничивает одновременные вызовы (не «веер» на 50 ссылок).
- [ ] `read_urls`/`extract` ≤10 ссылок, `crawl` ≤20 страниц, `yt_srt` ≤5 роликов.
- [ ] `X-RateLimit-*` и `Retry-After` читаются; числа лимитов не захардкожены.
- [ ] Длинные страницы читаются окнами (`meta.nextOffset`), а не одним запросом
      на 50 тыс. символов.

## 6. Контент — данные, не инструкции

- [ ] Текст страниц/Pdf/субтитров не исполняется и не подставляется в промпт как
      инструкция без пометки «недоверенное».
- [ ] Найденные в контенте команды, ссылки «подтверди вход», просьбы о ключах не
      выполняются.
- [ ] В ответ пользователю попадает пересказ со ссылкой, а не сырой текст
      страницы как готовая инструкция следующему шагу.
- [ ] Канон: [../../srezai-web/references/security.md](../../srezai-web/references/security.md).

## 7. Наблюдаемость

- [ ] В лог пишутся `tool`, `status`, `code`, `latency_ms`, `credits`, `attempt`;
      ключ и тела ответов — нет.
- [ ] URL в логах очищены от query-токенов (`?token=`, `?sign=`), PII не копируется.
- [ ] Есть счётчики: доля 401/402/429, p50/p95 латентности, кредиты в сутки.

## 8. Деградация

- [ ] При недоступности srezai сервис отвечает честно («данные не получены»), а
      не выдуманным результатом.
- [ ] Частичный результат помечается как частичный: что не прочитано и почему.
- [ ] Смена канала (REST → MCP → CLI) не происходит молча.

## 9. CI и релиз

- [ ] Smoke-набор (см. `examples.md`): `whoami` → `search` на 1–3 результата →
      `read` короткой страницы → `get_usage`; стоимость — единицы кредитов.
- [ ] Тест формы ответа: обязательные поля на месте, неизвестные поля не ломают
      парсер.
- [ ] Проверка, что код не зависит от точных текстов ошибок — только от `code`.
- [ ] Документация для команды: какой ключ, какие лимиты, что делать при 402/429.

## 10. После выката

- [ ] Первые сутки: 401/402/429 и расход кредитов в норме; p95 латентности не
      вырос.
- [ ] Сверка `get_usage` с ожидаемым бюджетом.
- [ ] Качество на реальных задачах — по методике
      [../../srezai-eval/SKILL.md](../../srezai-eval/SKILL.md), а не «на глаз».
